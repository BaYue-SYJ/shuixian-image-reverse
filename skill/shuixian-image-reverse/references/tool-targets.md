# 目标工具适配

同一段提示词投到不同工具，比例、负面词和语言的处理方式不同。动笔前先确认目标工具；用户没说时按“通用自然语言”写，并把比例写在正文首句。

各工具的参数与限制会随版本变化，下表按 2026-11 的公开文档整理，执行时以目标工具当前文档为准。无法确认的能力不要向用户断言。

## 速查

| 工具 | 比例怎么写 | 独立负面词 | 语言偏好 | 篇幅容忍 | 画面文字 |
|---|---|---|---|---|---|
| Midjourney v6/v7 | 参数 `--ar 3:4` | 无独立字段，用 `--no 元素` | 英文更稳，中文可用 | 短句＋参数，超过约 60 词后半段权重衰减 | 一般，短词可读 |
| Stable Diffusion / SDXL / Flux 的 ComfyUI 流程 | 设置宽高或空 latent | 有，双输入 | 关键词标签＋权重语法 | 75 token 一段，长词靠分段 | 差，不写清楚文字 |
| FLUX.1 | 正文描述或节点宽高 | 无（无 CFG 负向） | 自然语言 | 中长可用 | 一般 |
| FLUX.2 [pro]/[max] | 正文描述 | 无 | 自然语言 | 长句可用 | 较强 |
| gpt-image 系列（含自建 relay） | 只能选固定尺寸，靠首句声明方向 | 无 | 自然语言，中文原生可用 | 中长可用，过长会丢后段约束 | 强 |
| Nano Banana（Gemini 图像） | 正文描述，可要求“改成 3:4” | 无 | 自然语言，多轮可改 | 长句和多段可读 | 强 |
| 即梦 / Seedream | 界面选比例，正文再声明一次 | 无 | 中文原生 | 中长可用 | 中文文字较强 |
| 通义万相 / 可灵 / 智谱 / 文心 | 界面选比例 | 无 | 中文原生 | 中长可用 | 中文文字一般 |
| Ideogram | 界面选比例 | 有字段 | 英文更稳 | 中长 | 很强 |
| Recraft | 界面选比例＋风格预设 | 有字段 | 英文 | 中长 | 强，偏设计稿 |

## 比例三种写法

- **参数式**（Midjourney）：正文不提比例，末尾加 `--ar 3:4`。多个参数连写，`--ar 4:5 --style raw`。
- **固定档式**（gpt-image 系列）：只能在 1024×1024、1536×1024、1024×1536 中选，无法做到 7:5 这类精确比例。首句仍写目标方向（`约 7:5 横幅`），并告知用户实际会落在最接近的档位。
- **正文式**（对话式与中文原生工具）：首句写 `3:2 横幅`，若界面另有比例选项，两处保持一致；冲突时以界面设置为准，并在交付时提一句。

精确比例（如 `约 1:1.9`、`约 7:8`）只在正文式写法中保留，参数式和固定档式应取最接近的常用比例。

## 负面词三分法

1. **有独立字段**（SD、Ideogram、Recraft）：按需给 8—15 条英文短语，逗号分隔，只写确实造成偏差的具体项，不写通用质量词。
2. **伪支持**（Midjourney 的 `--no`）：把要排除的项写成 `--no a, b, c`，数量控制在三个以内，写多了会连主体一起压掉。
3. **不支持**（FLUX、gpt-image、Nano Banana、中文原生工具）：不输出 Negative Prompt 段落，改为正向可见结果。写法是“把不要的东西换成指定存在的东西”：

| 想排除 | 不要写 | 改成正向 |
|---|---|---|
| 杯碟被裁边 | 不要裁切 | `四边完整可见，底边留一线木桌` |
| 背景出现杂物 | 无杂物 | `背后是整面浅灰墙` |
| 变成彩色 | 黑白 | `整体只有黑白灰三档` |
| 多加一只手 | 不要多余的手 | `两人各一只手入画，另一只手垂在身侧` |

用户点名了不支持负面词的工具却仍要负面词时，说明原因，给正向替代写法，再附一份可用于其他工具的可选清单。

## 语言与篇幅

- 中文原生工具（即梦、通义、可灵、智谱、文心）直接用中文提示词，避免机翻英文导致主体名走样。
- 英文优先工具（Midjourney、SD、FLUX、Ideogram、Recraft）给英文，中文只作参考。专有名词和画面文字按原文保留。
- 中英双版是默认交付，但只在用户确实可能在两处使用时才值得写全；目标明确时给单语可省一半篇幅。
- 提示词越长，后段约束越容易被稀释。超过 350 字时，把最影响相似度的锚点前移，把材质、背景细节后置或删掉。

## 有参考图时的附加通道

用户打算在生成时附参考图，提示词的分工写法要跟着工具走：

| 工具 | 参考图通道 | 提示词侧重 |
|---|---|---|
| Midjourney | `--sref` 风格、`--cref` 角色 | 只写新内容与要保留的特征，不重复描述图里已有的东西 |
| SD / ComfyUI | IP-Adapter、ControlNet（线稿、深度、姿态） | 写明用哪一路控制：`沿用线稿的轮廓，重新配色` |
| gpt-image | 图像编辑 / 多图输入 | 写“保留图一的构图，把主体换成……”，改动点逐条列 |
| Nano Banana | 多图输入、多轮对话 | 可分轮：先定构图，再换主体，最后调色 |

多图输入时按图号分工：`图一提供版式与留白，图二提供配色`。工具只接受单图时，说明冲突并让用户选一路，或先把两张合并成一张参考图。

## 交付时的提示

- 用户没说工具，按通用自然语言写，不堆参数；末尾一句说明“若投 Midjourney 需另加 `--ar`，若投 gpt-image 只能取最接近的比例档”。
- 交付里出现参数、尺寸档位或负面词时，确保与目标工具当前支持一致；不确定就写通用写法，不要编造参数名。
